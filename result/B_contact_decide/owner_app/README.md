# Porchlight — owner app (no login)

Folder: `result/B_contact_decide/owner_app/` (the contact & decide channel of Part B, next to Telegram).

Mobile-first app where a business owner approves, edits or declines the holiday hours we suggest, one swipe per day.
It shows the real bundles from Part B (Supabase tables `bundles`, `bundle_items`, `decisions`, `apply_log`) and sends
every decision to the n8n workflow `Connect · Web action` (spec: `result/n8n/WEB_ACTION.md`), which writes to Yext
through the same `Connect · Apply to Yext` as the Telegram flow.

## Routes

| URL | What |
|---|---|
| `/o/<entity_id>?t=<token>` | The owner's link from our message. `token` = first 32 hex of HMAC-SHA256(entity_id, `LINK_SECRET`); print it with `python3 result/B_contact_decide/owner_link.py FI-D0017 --base https://<app>` |
| `/` | The demo business FI-D0017 Kahvila Kipinä (new customer, no history) |

## Environment (server only)

Set these in Lovable Secrets (or the host's environment). They are read only by the server functions in
`src/lib/connect/api.ts`; the browser never sees them. Never commit them.

| Variable | Used for |
|---|---|
| `SUPABASE_URL`, `SUPABASE_SERVICE_KEY` | reading the bundles of one entity |
| `N8N_WEB_ACTION_URL` | the webhook of `Connect · Web action` |
| `LINK_SECRET` | checking the link token |

Without `SUPABASE_URL` the app runs in **demo mode** on the bundled sample (`src/lib/connect/demo.generated.ts`) and
sends nothing; a note on the screen says so.

## What the screen shows, and where it comes from

| On the card | Source |
|---|---|
| Holiday name, date | `bundle_items.day_name` → name in the owner's language from `data/calendar_special_days.csv`; `date` |
| Shown now → suggested | `shown_hours` → `proposed_hours` |
| Confidence | `confidence` (HIGH / MEDIUM / LOW) as words and a 3-step meter (no invented percentage) |
| Why | the reason for `basis` (same words as the Telegram text); for peer-based items the share of closed peers read from `evidence` |
| Shows on | `bundles.publishers` with `typicalUpdateSpeedSeconds` |
| Card type | `route`: SUGGEST = approve / skip / edit; ASK = closed / open as usual / edit; AUTO_APPLY only in Activity; STAFF and SKIP never shown |
| Activity | decided items (`final_hours`, or a `decisions` row with `parsed.date`) and `apply_log` status |
| "Our message" | the bundle's real `intro_text` |

Holiday names and reasons are generated by `python3 result/B_contact_decide/export_frontend_data.py`
(`src/lib/connect/*.generated.ts`, do not edit by hand). Review replies and Google Posts were removed from the
Lovable mock: there is no data or pipeline for them.

## Develop

```sh
cd result/B_contact_decide/owner_app
npm install
npm run dev        # demo mode
npx vitest run     # deck mapping and parser tests

# live data on your machine (reads SUPABASE_*, N8N_WEB_ACTION_URL, LINK_SECRET from the repo-root .env)
set -a && . ../../../.env && set +a && npm run dev -- --port 5180
```

## Deploy on Vercel

1. Vercel → Add New Project → import `Pbi-with-love/SinceAI-Porchlight`.
2. **Root Directory**: `result/B_contact_decide/owner_app`. Framework preset: Other (Vite). Build command and output are
   picked up by Nitro, which detects Vercel and builds with its `vercel` preset (no config change needed).
3. Environment Variables (Production and Preview): `SUPABASE_URL`, `SUPABASE_SERVICE_KEY`, `N8N_WEB_ACTION_URL`,
   `LINK_SECRET` (the same value as in `.env`, so `owner_link.py` makes valid links).
4. Deploy, then print the owner link with the Vercel domain:
   `python3 result/B_contact_decide/owner_link.py FI-D0017 --base https://<project>.vercel.app`
